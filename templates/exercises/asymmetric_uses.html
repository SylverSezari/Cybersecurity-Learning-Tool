Öffentliche und private Schlüssel

Asymmetrische Kryptografie im Alltag

Beim Surfen im Internet, Anmelden mit einem Passkey oder Installieren eines Updates kommen oft asymmetrische Verfahren zum Einsatz. Sie helfen, Identitäten zu prüfen, Schlüssel zu vereinbaren und digitale Signaturen zu kontrollieren.

Wie RSA & Co. das Internet absichern

Vier moderne Einsatzgebiete mit Beispielen aus dem Alltag

  1. Sicheres Surfen (HTTPS / TLS) – Hybride Verschlüsselung:

    Jedes Mal, wenn du im Browser eine Webseite wie sbb.ch, dein E-Banking oder die Lernplattform der Kanti aufrufst, arbeiten symmetrische und asymmetrische Verschlüsselung Hand in Hand. Dieses Zusammenspiel nennt man hybride Verschlüsselung:

    • Schritt 1 (Asymmetrisch): Dein Browser und der Webserver kennen sich noch nicht. Über das TLS-Protokoll nutzt dein Browser den Public Key des Servers, um einen frisch erzeugten, geheimen AES-Sitzungsschlüssel sicher mit dem Server auszutauschen. Nur der Server kann diesen Schlüssel mit seinem Private Key entschlüsseln.
    • Schritt 2 (Symmetrisch): Sobald beide Seiten denselben geheimen AES-Schlüssel besitzen, schalten sie um. Der gesamte restliche Datenverkehr (Webseite, Bilder, Passworteingabe) läuft ab sofort blitzschnell über AES.

  2. Digitale Signaturen und Software-Updates (Echtheitsprüfung):

    Bei der asymmetrischen Kryptografie lässt sich das Prinzip auch umdrehen, um die Echtheit (Integrität und Authentizität) von Daten zu beweisen. Man spricht dann von einer digitalen Signatur:

    • Der Absender berechnet einen digitalen Fingerabdruck (Hashwert) einer Datei und verschlüsselt diesen mit seinem eigenen Private Key.
    • Jede empfangende Person kann diese Signatur mit dem bekannten Public Key des Absenders prüfen. Gelingt dies, ist mathematisch bewiesen, dass die Datei wirklich vom Absender stammt und unterwegs nicht manipuliert wurde.
    • Alltagsbeispiele: Bevor dein Smartphone oder Laptop ein System-Update von Apple, Microsoft oder Google installiert, prüft das Gerät dessen digitale Signatur. Auch rechtsgültige elektronische Unterschriften auf PDF-Verträgen (z. B. über SwissID oder Skribble in der Schweiz) funktionieren genau nach diesem Prinzip.

  3. Ende-zu-Ende-verschlüsselte Messenger (Threema, Signal, WhatsApp)

    Wenn du über einen modernen Messenger wie den Schweizer Dienst Threema oder Signal eine Nachricht verschickst, soll niemand unterwegs mitlesen können – nicht einmal die Betreiberfirma der Server selbst.

    • Wie es funktioniert: Bei der Einrichtung der App erzeugt dein Smartphone ein eigenes Schlüsselpaar. Der Private Key verlässt dein Handy niemals; der Public Key wird auf dem Server hinterlegt.
    • Wenn dir eine Kollegin schreibt, holt sich ihr Smartphone deinen Public Key und verschlüsselt damit den Nachrichtenschlüssel. Selbst wenn die Server des Messenger-Anbieters gehackt würden, lägen dort nur unlesbare Daten, weil nur dein Smartphone den passenden Private Key besitzt.

  4. Passkeys – Einloggen ohne klassisches Passwort

    Moderne Logins setzen zunehmend auf Passkeys (z. B. bei Google, Apple, Digitec Galaxus oder im Passwort-Manager Bitwarden). Auch dahinter steckt reine asymmetrische Kryptografie:

    • Beim Einrichten eines Passkeys erzeugt dein Smartphone ein Schlüsselpaar. Der Public Key wird beim Online-Dienst gespeichert, der Private Key bleibt geschützt im Sicherheitschip deines Smartphones.
    • Beim Einloggen schickt dir der Server eine zufällige Zahlenfolge (eine sogenannte Challenge). Dein Handy signiert diese Aufgabe – nach deiner Freigabe per Face ID oder Fingerabdruck – mit dem Private Key und schickt sie zurück. Der Server prüft die Unterschrift mit deinem Public Key und lässt dich einloggen, ohne dass jemals ein geheimes Passwort über das Internet gesendet wurde.

Wie weiss ich, wem ein Public Key gehört?

Digitale Zertifikate

Eine wichtige Sicherheitsfrage bleibt: Wenn jeder einen Public Key veröffentlichen kann – woher weiss dein Browser beim E-Banking, dass der empfangene Public Key tatsächlich deiner Bank gehört und nicht einem Betrüger?

Die Antwort sind digitale Zertifikate. Ein digitales Zertifikat funktioniert wie ein elektronischer Reisepass für Webseiten: Eine weltweit anerkannte, vertrauenswürdige Prüfstelle – eine sogenannte Zertifizierungsstelle (Certificate Authority, kurz CA) – bestätigt mit ihrer eigenen digitalen Signatur, dass ein bestimmter Public Key eindeutig zu einer bestimmten Domain (z. B. ubs.ch oder admin.ch) gehört. Dein Browser prüft dieses Zertifikat bei jedem Seitenaufruf automatisch im Hintergrund.

Merksatz: Symmetrische Verschlüsselung (AES) ist der schnelle Transporter für grosse Datenmengen. Asymmetrische Verschlüsselung (RSA / ECC) ist der sichere Schlüsselaustausch und der digitale Notar, der Echtheit beweist.

Wähle die Aufgabe des Schlüssels

Dein Browser verwendet beim Öffnen einer Webseite über HTTPS nicht ausschliesslich RSA, sondern kombiniert RSA (bzw. ein anderes asymmetrisches Verfahren) mit dem symmetrischen Verfahren AES.

Weshalb werden beide Methoden angewendet?

Du meldest dich mit einem Passkey auf deinem Smartphone bei einem Online-Dienst an.

Weshalb ist diese Methode so gut gegen klassische Phishing-Websites geschützt?

Zwei Kantonsschülerinnen chatten über einen Ende-zu-Ende-verschlüsselten Messenger wie Threema oder Signal miteinander.

Weshalb kann selbst der Betreiber der Server, über welche die Nachrichten weitergeleitet werden, den Inhalt des Chats nicht lesen?

Ein Softwarehersteller möchte ein wichtiges Sicherheitsupdate veröffentlichen. Damit alle Nutzerinnen und Nutzer überprüfen können, dass die Update-Datei tatsächlich vom Hersteller stammt und unterwegs nicht verändert wurde, versieht der Hersteller die Datei mit einer digitalen Signatur.
